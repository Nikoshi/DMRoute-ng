= RepeaterRegistry & Domänenmodell

== Zweck
Verwaltung des Repeater-Zustands, der Homebrew-Authentifizierungsdaten (Challenge/Response) und der Stations-Konfiguration.

== Zustandsmaschine (RepeaterState)
* `ChallengeSent`: Zufallszahl (`RandomNumber`) an Repeater gesendet; wartet auf SHA-256-Antwort.
* `LoggedIn`: Authentifizierung erfolgreich; Repeater ist im Routing aktiv.
* `Disconnected`: Verbindung getrennt oder Timeout überschritten.

== Thread-Sicherheit
* Nutzung eines `ConcurrentDictionary<int, Repeater>` für atomare Operationen.
* Mutierende Eigenschaften am `Repeater`-Objekt müssen bei parallelen Netzwerk-Events im DmrServer-Loop berücksichtigt werden.
* Der Paket-Router enumeriert nicht direkt das `ConcurrentDictionary`. Er liest einen Array-Snapshot, der bei Anmeldung oder Topologieänderungen außerhalb des stetigen Paketpfads erneuert wird.
* Netzwerkendpunkte werden als `Ipv4Endpoint`-Werte gespeichert; dadurch sind Vergleich und Übergabe im Routing frei von Endpoint-Allokationen.
* Nur ein gültiges `RPTL` darf einen dynamischen Repeater-Eintrag anlegen. DMRD-, Ping-, Key- und Config-Pfade verwenden ein reines Lookup, damit unbekannte IDs keine Objekte oder PSK-Strings erzeugen.
