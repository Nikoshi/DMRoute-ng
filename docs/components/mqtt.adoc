= MqttIntegrationService & Telemetrie
:toc:
:sectnums:

== Übersicht
Der `MqttIntegrationService` ist ein Background-Worker, der Netzwerkzustand und Echtzeit-Ereignisse asynchron über einen MQTT-Broker publiziert. MQTT liegt außerhalb der harten Hot-Path-Garantie, verwendet aber begrenzte und wiederverwendete Puffer.

== Architektur & Performance
Die Anbindung an den `MicroSubnetRouter` und das `SdsGateway` erfolgt über einen begrenzten In-Memory-Kanal (`System.Threading.Channels`). Dadurch blockiert MQTT-Netzwerklatenz den UDP-Empfang nicht. Die JSON-Serialisierung schreibt in wiederverwendete Puffer; fertige SMS-Strings und Verbindungswechsel dürfen weiterhin allokieren.

Der `RawMqttClient` besitzt einen festen Paketpuffer. TCP-Sends werden bis zur vollständigen Übertragung wiederholt und die CONNACK-Antwort wird auch bei fragmentiertem Empfang vollständig eingelesen. Nach einem Verbindungsfehler wird für den nächsten Versuch ein neuer Socket angelegt.

== MQTT Topic-Baum
Der Basis-Pfad lautet `dmroute/{zoneId}/`.

=== Calls

* `calls/active/{dstId}/{srcId}`: retained JSON bei Rufstart. Beim Rufende wird das retained Topic mit leerem Payload gelöscht.
* `calls/history/{dstId}/{srcId}`: nicht-retained JSON bei sauberem Ende oder Timeout, einschließlich Rufdauer und Zeitstempel.

Das Feld `type` unterscheidet `GroupCall` und `PrivateCall`.

=== Roaming

* `roaming/guests/{deviceId}`: retained Status für eine fremde Teilnehmer-ID, die an einem lokalen Hotspot gesehen wurde.
* `roaming/away/{deviceId}`: retained Status einer lokalen Teilnehmer-ID, deren Aufenthaltszone über das Mesh gemeldet wurde.

Beim Ablauf eines Eintrags wird das jeweilige retained Topic mit leerem Payload gelöscht.

=== SMS

* `sms/{dstId}/{srcId}`: retained JSON mit dekodiertem Text und Zeitstempel.

SMS ist wegen unterschiedlicher SDS-Varianten der Funkgeräte und Hotspots weiterhin best-effort implementiert. Der Hardware-Test bewertet Transport, Reassembly und Dekodierung deshalb einzeln.
